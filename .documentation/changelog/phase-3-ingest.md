# Phase 3 — Ingest + Maintenance

> Three more Karpathy-pattern primitives: atomic source ingest with provenance, a structured append-only session log, and auto-regenerated hierarchical indexes. Plus a cross-note broken-link lint that the Phase 2 per-note validator couldn't do.

## What Phase 3 adds

1. **`ingest_source` MCP tool** — takes a source (URI + title + optional summary/tags) and an array of extracted units (each a path + content + optional type/frontmatter). Builds a ChangeSet that creates one `sources/<slug>.md` (type=source) plus one note per unit with `derived_from` stamped to the source-note. Routes through `apply_patch`.
2. **Structured log.md** — append-only log at the vault root, `log_event` writes, `log_query` reads. Dual-format: human line + fenced `yaml event` block. Parse is line-by-line (no external YAML dependency on read).
3. **Hierarchical index auto-regen** — `applyPatch` now regenerates `INDEX.md` in each affected directory unless `regenIndexes: false`. Overflow threshold at 100 entries flags the directory as "consider splitting."
4. **Broken-link lint** — `find_broken_links` MCP tool + `broken_links` rule in `lint_vault`. Resolves `[[wikilinks]]` against the set of actual note basenames; flags misses as warnings.

## Under the hood

### `src/core/ingest.ts` — `buildIngestChangeSet(input)`

Input shape:
```ts
{
  source: { source_uri, source_title, source_type?, source_path?, source_summary?, source_tags? },
  units:  [{ path, content, title?, type?, extra_derived_from?, extra_frontmatter?, confidence? }]
}
```
Emits exactly `1 + units.length` creates. The source note's default path is `sources/<slugified title>.md`. Unit notes get `derived_from: [<source_path>, ...extra_derived_from]` so `missing_provenance` is automatically satisfied.

The MCP tool layer additionally calls `log_event({ kind: "ingest", ... })` on successful apply — the ingest is a first-class entry in `log.md`.

### `src/core/log.ts` — structured log

File format (one entry):
```
- 2026-04-22T00:00:00Z — ingest: added 3 notes from RFC-1234
```yaml event
ts: 2026-04-22T00:00:00Z
kind: ingest
summary: "added 3 notes from RFC-1234"
payload:
  source_path: sources/rfc-1234.md
  unit_paths: ["notes/a.md", "notes/b.md", "notes/c.md"]
  source_uri: "https://example.com/rfc-1234"
```

Parser is an intentionally-minimal line scanner matching the shape we emit — no external YAML dep in the read path, so log.md stays parseable even with transient YAML-library version drift.

### `src/core/index-regen.ts` — hierarchical index regen

`regenDirectoryIndex(vaultPath, dirRel)`:
- Reads `*.md` in `<dirRel>` (non-recursive; excludes `INDEX.md` and `README.md`).
- Builds `IndexEntry { path, title, summary }`. Title from frontmatter > first heading > basename; summary from frontmatter `purpose` > first non-heading paragraph (truncated to 140 chars).
- Sorts alphabetically by title; renders markdown with both `[visible](./path)` and `[[wikilink]]` for each.
- Header includes a clear "auto-generated by semantic-sidekick" warning so users know not to hand-edit.
- Idempotent — compares rendered body to existing `INDEX.md`, skips write if unchanged.
- Overflow signal — when `entryCount > 100`, prepends a split-recommendation banner. Phase 3 does not auto-split; Phase 4/5 can add the policy.

`regenIndexesForPaths(vaultPath, paths)` walks the immediate parent directory of each path, dedupes, and calls `regenDirectoryIndex` per directory. `applyPatch` invokes this automatically on `creates`/`deletes`/`moves` unless `regenIndexes: false`.

### Broken-link lint

`lintVault` now does two passes: first builds a set of known note basenames across all scanned files, then validates each note (schema + broken-links) against that set. Skips wikilinks inside fenced code and inline code. Exposed as:
- `find_broken_links` MCP tool — returns just the `broken_links` subset.
- `lint_vault` — full report including broken-link findings under `byRule.broken_links`.

Broken links are always `severity: warn`; intentionally not blocking because new notes frequently reference planned-but-not-yet-filed companions.

## Invocation surfaces

| Action | Surface |
|---|---|
| File a paper/blog post and its extracted units | MCP `ingest_source` (Claude reads the source, extracts, calls the tool) |
| Record a session/decision/incident marker | MCP `log_event` |
| Answer "when did we ingest X? / what decisions were logged this week?" | MCP `log_query` |

| Find dead wikilinks before merging a vault PR | `semantic-sidekick lint --notes <vault> --rule broken_links` or MCP `find_broken_links` |

## Failure modes

| Symptom | Cause | Fix |
|---|---|---|
| ingest_source creates a duplicate source-note with a slug suffix | Caller reused `source_title` but supplied a distinct `source_path` | Pass the existing source-note's path explicitly as `source.source_path` so apply_patch's precheck catches the collision |
| INDEX.md marked `wrote: false` every apply_patch | Rendered content is byte-identical to the existing file — no-op is correct | Not a bug |
| Overflow warning doesn't split | Intentional — Phase 3 flags, Phase 4+ decides the split policy | Move notes into subdirs manually, rerun `regenerate_index` |
| Broken-link lint flags `[[INDEX]]` | INDEX.md is excluded from the known-names set when scanned as the index | Use `[[INDEX.md]]` or rename the link — INDEX files are not intended as wikilink targets |
| log.md grows unboundedly | Phase 3 does not rotate | Phase 3 defers rotation to a nightly/weekly maintenance task; Phase 4 can wire it up when `outage-silence` mode rotates on entry |
| log_query returns no results despite log.md having entries | Entries added by something other than `logEvent` (raw writes) — parser only matches our emission shape | Use `logEvent` to append, or match the exact block format |

## Known gaps (Phase 3 scope boundary)

- No fetch layer in `ingest_source` — the tool accepts pre-extracted units, not raw URLs. Fetch + extraction is Claude's job (uses its own tools) before calling `ingest_source`.
- No per-note graph rewire on apply_patch — the vector/graph indexes are still rebuilt by the file watcher or `--reindex`, not by apply_patch. Acceptable: watcher catches changes in real time, hook-path searches use the parsed-doc cache.
- No contradiction detection — gated to Phase 5 by the plan.
- Log rotation not automated — Phase 4's outage-mode can piggyback on this.
