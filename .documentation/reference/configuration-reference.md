# Configuration reference

## Files

### `.claude-plugin/plugin.json`
Plugin manifest. Name, description, version, keywords.

### `.claude-plugin/marketplace.json`
Marketplace descriptor — lets `/plugin marketplace add` register this repo. Per project memory: `metadata.version` AND `plugins[0].version` must bump in lockstep with `package.json`.

### `.mcp.json` (per-project)
MCP server registration. Written by the SessionStart reconcile hook. Expected shape (v1.1.1+):
```json
{
  "mcpServers": {
    "semantic-vault": {
      "type": "stdio",
      "command": "node",
      "args": ["./node_modules/@theglitchking/semantic-memory/bin/semantic-memory",
               "--notes", "./path/to/vault"]
    }
  }
}
```
Mid-migration installs may have `@theglitchking/semantic-sidekick/bin/semantic-sidekick` instead — `findLocalBin` prefers the new path with legacy fallback. Gitignored by default. Regenerated on SessionStart by `hooks/reconcile.js`.

### `.claude/settings.json` (per-project)
Project-level Claude Code settings. Hooks auto-merge from plugin's `hooks/hooks.json`. Can override:
- `permissions.allow[]` / `permissions.deny[]`
- `env.<VAR>` — environment variables for hook/tool invocations
- `statusLine` — custom status bar command
- `hooks.<event>[]` — additional hooks beyond the plugin

### `.claude/CLAUDE.md` (per-project)
Repo-specific augmentation. In v1.2+, opens with a pointer to `<projectRoot>/AGENTS.md` as the primary contract. Contributes:
- Vault-first rule (Phase 1)
- Routing / mode indicator rule (Phase 4)

### `<projectRoot>/AGENTS.md` (v1.1+)
Canonical agent contract artifact with managed-block markers. Generated by `regenerate_contract`. Local Notes section outside the markers is preserved across regenerations. NOT gitignored — commit it. See [contract-guide.md](../operational/contract-guide.md).

### `<vault>/vault.schema.yml`
Per-vault schema override. If absent, the default from `src/core/schema-default.ts` applies. Install with `semantic-memory install-schema --notes <path>` or via the `install_schema` MCP tool.

### `<vault>/.semantic-sidekick-index/` — index artifacts (gitignored)
Path retains legacy name through all of v1.x per the v1.0 storage promise. v2.0 will move to `.claude/.semantic-memory/index/`.

- `hnsw.bin`, `hnsw-meta.json` — HNSW vector index.
- `embeddings.json` — per-chunk vectors, keyed by `<path>:<chunkIndex>`.
- `graph.json` — built graph.
- `meta.json` — model, dimensions, totalChunks, indexedAt.
- `docs.cache.json` — Phase 2 parsed-doc cache (drops hook latency 9x).

### `<vault>/log.md` — the durable state log (tracked with vault content)
Append-only. Format per entry:
```
- <iso-ts> — <kind>: <summary>
```yaml event
ts: <iso-ts>
kind: <kind>
summary: "<summary>"
payload:
  key: value
```
```

### `<vault>/proposals/<date>-<slug>.md` (v1.1+)
Review-first synthesize_note targets. Generated by `synthesize_note({proposal: true})`. Each carries `status: proposal` and `proposed_target` frontmatter; `synthesize_promote` moves them to canonical destinations. Commit when reviewed.

## Per-project runtime state

### v1.2+ canonical paths — `<project>/.claude/.semantic-memory/`

| File | Written by | Read by | Reset on |
|---|---|---|---|
| `mode` | `/mode` command + SessionStart hook | UserPromptSubmit + Stop hooks | SessionStart (resets to `vault-first`) |
| `fingerprints.json` | UserPromptSubmit hook | UserPromptSubmit hook | Manual `rm`; not auto-reset |
| `capture-pending.json` | UserPromptSubmit hook | Stop hook | SessionStart; Stop after emit |
| `session.json` (v1.1+) | `session_start` MCP tool | session tools, Stop hook, healthcheck | `session_finish` removes the file |
| `healthcheck-cache.json` (v1.1+) | `runHealthcheck` | `runHealthcheck` | 5-minute TTL or `--force` |

### Legacy paths — `<project>/.claude/.sidekick-*` (v1.x readable, v2.0 removed)

| File | Status | Migration |
|---|---|---|
| `.sidekick-mode` | Read-fallback only | `bin/semantic-memory migrate-state` → `.semantic-memory/mode` |
| `.sidekick-fingerprints.json` | Read-fallback only | → `.semantic-memory/fingerprints.json` |
| `.sidekick-capture-pending.json` | Read-fallback only | → `.semantic-memory/capture-pending.json` |
| `.semantic-sidekick-update-cache.json` | Plugin runtime cache | TTL-based; safe to delete |
| `.sidekick-update-cache.json` | Pre-rebrand legacy | Safe to delete |

All are gitignored by default. See [state-migration.md](../operational/state-migration.md).

## Recommended `.gitignore` (v1.2.0+)

The shipping `.gitignore` covers everything. For a fresh repo using semantic-memory:

```gitignore
# Dependencies
node_modules/

# Build output
dist/

# Vault index — derived, rebuilds on demand
.semantic-sidekick-index/

# Environment
.env
.env.local

# Claude Code local overrides
.claude/settings.local.json

# Memory is personal — folder is tracked, contents are not
.claude/memory/*
!.claude/memory/.gitkeep
.planning/
.mcp.json

# Skill eval workspaces (test artifacts, never ship in plugin distribution)
skills/*-workspace/

# Local build / test artifacts
*.tgz
.claude/.semantic-sidekick-update-cache.json

# Other-plugin runtime caches (postinstall artifacts from any plugin)
.claude/.*-update-cache.json

# Sidekick-era (legacy) state — readable through v1.x via fallback
.claude/.sidekick-mode
.claude/.sidekick-fingerprints.json
.claude/.sidekick-capture-pending.json

# Plugin runtime state files (sidekick-era and current)
.claude/semantic-sidekick.json
.claude/semantic-memory.json

# v1.2: state files consolidated under .claude/.semantic-memory/
.claude/.semantic-memory/

# Stale semantic-first symlink (points at npx cache — regenerated per machine)
.claude/skills/semantic-first

# npm publish auth token (never commit credentials)
.npmrc
```

Note that **AGENTS.md is NOT gitignored** — commit it. The Local Notes tail is per-project knowledge that needs versioning.

## Environment variables

### Read by hooks / CLI
| Variable | Source | Effect |
|---|---|---|
| `SIDEKICK_DEBUG` | User-set | `=1` enables stderr debug log in vault-context.js. Name kept across rebrand. |
| `SIDEKICK_VAULT_PATH` | User-set (test) | Overrides `.mcp.json`-derived vault discovery. Name kept across rebrand. |
| `CLAUDE_STOP_HOOK_ACTIVE` | Claude Code | `=1` during Stop-block reentry; hook loop guard |
| `CLAUDE_PROJECT_DIR` | Claude Code | Project root (preferred over `cwd` from stdin) |
| `CLAUDE_PLUGIN_ROOT` | Claude Code | Plugin install dir (used in hooks.json commands) |

The `SIDEKICK_*` variable names retain the legacy prefix for backwards compat. Don't break user shell configs.

### Read by Node runtime
| Variable | Effect |
|---|---|
| `NODE_OPTIONS=--max-old-space-size=4096` | Raise heap if reindex fails OOM on large vaults |

## Schema (`vault.schema.yml`) fields

Defaults — see `src/core/schema-default.ts` for the ground truth.

### `version` (number)
Schema format version. Current: 1.

### `provenance_fields` (string[])
Field names that constitute provenance. Default: `[sources, derived_from, last_verified, status, confidence]`.

### `status_enum` (string[])
Allowed values for `status` frontmatter. Default: `[draft, active, stale, deprecated, archived, proposal]` (proposal added in v1.1+).

### `confidence_enum` (string[])
Default: `[high, medium, low]`.

### `severity_enum` (string[])
For `gotcha` type. Default: `[low, medium, high, critical]`.

### `types` (map)
```yaml
types:
  <type-name>:
    description: str  # optional
    required: [<field>, ...]  # list of required frontmatter keys
```
Default types: `note`, `decision`, `gotcha`, `source`.

### `lint` (map)
```yaml
lint:
  missing_provenance:
    applies_to: [note, decision, gotcha]  # list of types to check
    severity: warn                         # warn | error
  stale:
    max_age_days: 180                      # 0 = disabled
    severity: warn
  schema_violations:
    severity: error                        # blocks apply_patch when validate=true
```

## Hook tuning (edit source, no config)

| Setting | Location | Default | Meaning |
|---|---|---|---|
| UserPromptSubmit limit | `hooks/vault-context.js:handlePrompt` | 8 | Top-K hits injected per prompt |
| SessionStart limit | `hooks/vault-context.js:handleSessionStart` | 6 | Top-K hits in sessionstart preload |
| Fingerprint ring size | `hooks/vault-context.js:handlePrompt` | 10 | How many recent prompts to dedup against |
| State-delta window | `hooks/vault-context.js:handleSessionStart` | 14 days | Log entries surfaced in `<vault-state-since>` |
| Search timeout | same file | 30s | Max time to wait for search CLI |
| Prompt min length | `handlePrompt` | 8 chars | Below this, no search fired |
| Capture cue regexes | `hooks/vault-context.js:CAPTURE_CUES` | 5 patterns | Trigger words for capture-pending append |
| Drift cache TTL (v1.1+) | `src/core/healthcheck.ts:CACHE_TTL_MS` | 5 min | Healthcheck result cache lifetime |
| Session staleness threshold (v1.1+) | `src/core/session.ts:STALE_THRESHOLD_MS` | 24h | When `session_status` reports stale |
| Session run timeout default (v1.1+) | `src/core/session.ts:DEFAULT_TIMEOUT_MS` | 5 min | Default `session_run` command timeout |

These are code constants, not config — edit the file + rebuild if you need different values. Intentional: keeps the config surface small.

## Plugin auto-update policy (`semantic-memory.json`)

Written by the plugin runtime to `.claude/semantic-memory.json` (was `.claude/semantic-sidekick.json` pre-v1.1.1):

```json
{ "updatePolicy": "nudge" }
```

Values:
- `nudge` (default) — SessionStart shows a one-line upgrade reminder when a newer version is on npm.
- `auto` — auto-runs `npm update` on SessionStart if a newer version exists.
- `off` — no upgrade checks.

Change via `/policy <value>` or edit the file directly.

The legacy `.claude/semantic-sidekick.json` is still read as a fallback for mid-migration installs.
